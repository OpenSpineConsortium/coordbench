    Add Allow header on 405 responses (core + middleware)
    
    chi now collects the methods registered on the matched route when the path
    matches but the request method does not, and the default 405 handler lists
    them in Allow, in method order, as RFC 9110 asks. middleware.SetAllowHeader
    adds the same header ahead of routing for apps that set their own 405 handler.
    Only the 405 path does any extra work.

    Add built-in CORS support
    
    CORSOptions and DefaultCORSOptions configure a CORS middleware that sets the
    Access-Control-* headers and answers OPTIONS preflights with a 204. Mux gets
    EnableCORS, EnableCORSWithOptions and WithCORS; they install a
    method-not-allowed handler that answers preflights and lists the path's
    methods in the Allow header of a 405. methodNames and GetMethodName map a
    method type back to its name.
