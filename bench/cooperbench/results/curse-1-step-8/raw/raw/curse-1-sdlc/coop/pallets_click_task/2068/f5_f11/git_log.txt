    Add editor process monitoring to click.edit()
    
    A new monitor_process parameter takes a callback, or a mapping or object
    with a callback and a poll_interval. While edit waits for the editor, a
    background thread calls callback(event_type, process_id, editor_command,
    timestamp) for start, suspend and resume (where /proc can tell) and
    terminate. A callback that raises issues a UserWarning and the following
    events are still delivered.

    Add lock_files to click.edit to stop concurrent edits of one file
    
    With lock_files=True the editor makes an exclusive lock file named
    .{filename}.lock beside the file before it starts, holding the process
    id and the time, and removes it in a finally clause, so a failing
    editor, an OSError or a KeyboardInterrupt never leaves it behind. An
    existing lock means another session has the file, so the edit is
    refused with a ClickException and that lock is left alone. The default
    is False, so nothing changes for existing callers.
